## 数据库迁移现状

- 基线 `0001_initial_baseline.sql`：空库执行（app_users 含 `is_admin`、shops、shop_members、角色/权限、employees、employee_work_*、ledger_*）；
- `0002_drop_pricing_tables.sql`：清理已下线定价表；
- `0003_shop_ledger_refactor.sql`：旧库重构（studios→shops、字段改名、删商品表、旧 owner 升级为管理员、加台账表），空库执行为条件空操作；
- `0004_ledger_text_and_tracking.sql`：台账明细改 text 保存原始值并补充跟踪号；
- `0005_import_idempotency.sql`：为员工工作和台账批次增加导入幂等键；
- `0006_rbac_catalog.sql`：补齐 admin/leader/customer 角色、基础权限码与预置角色权限，生产发布不依赖可选 seed；
- `0007_ledger_stats_permission.sql`：增加台账统计查看权限，仅预置给管理员；
- `0008_ledger_sku_order_unique_and_edit.sql`：跟踪号迁移为 SKU、历史订单号去重并建立全局唯一索引、增加 `ledger.edit` 权限；
- `0009_customer_employee_work_import.sql`：客服角色增加 `employee_work.import`，启用店铺成员可直接导入员工工作；
- `0010_ledger_order_month_range.sql`：增加并回填台账订单年月，支持月份区间筛选；
- `0011_ledger_tail_fee.sql`：赔偿迁移为尾程，统一默认 `2%` 并回算历史利润；
- `0012_shipping_rate_versions.sql`：新增物流资费版本与规则表，迁入 89 条初始规则并记录重量重算所用版本；
- `0013_ledger_soft_delete.sql`：台账增加删除时间和操作者；订单号唯一约束仅作用于当前台账，支持回收站恢复；
- 迁移执行器使用 advisory lock，事务执行，失败整体回滚；生产执行前必须 `pg_dump`；
- seed 幂等：角色/权限目录 upsert、管理员账号、默认店铺（`SEED_SHOP_NAME` 或"默认店铺"）。

## 迁移验收约束

- 页面组件只依赖前端 services，不依赖 PostgreSQL 驱动；
- Node.js API 通过稳定业务接口隔离数据库实现；
- `employee_work_batches`、`employee_work_items` 和 `app_users` 的业务字段保持稳定；
- `created_by` / `uploaded_by` 始终由服务端从已验证登录身份产生；
- 至少保留一份可恢复的 PostgreSQL 备份；
- v1 不使用 Kubernetes、负载均衡和多机集群。
