# 选品工具需求文档（v1.0）

## 1. 项目概述

| 项目 | 内容 |
|---|---|
| 项目名称 | 团队选品工具（sku-table） |
| 目标用户 | 电商小团队 3~5 人（选品员、客服/运营、负责人） |
| 核心价值 | 集中管理商品数据，可追溯"谁选的"，支持客服跟进备注 |
| 形态 | Web 应用（PC 浏览器为主），内部使用，非商业产品 |

## 2. 背景与问题

- 现状：商品数据散落在 Excel 文件里，靠微信/网盘传来传去，版本混乱。
- 痛点：
  1. 不知道某个商品是团队里谁选回来的；
  2. 客服/运营对商品的处理状态（已联系供应商、价格待核实等）没有地方记录；
  3. 多人同时维护同一份数据容易冲突、覆盖。
- 目标：一个"登录即可用"的网页工具，导入 Excel → 集中筛选/查看 → 在线改备注。

## 3. 用户角色与权限

| 角色 | 说明 | 权限（v1） |
|---|---|---|
| 负责人（管理员） | 妹夫 | 负责开通团队成员；管理员功能（v1.1 起） |
| 选品员 | 负责找品、导入 Excel | 导入、查看全部、编辑内部备注 |
| 客服/运营 | 负责跟进商品 | 查看全部、编辑内部备注 |

权限规则（v1 简化版）：

- 仅已开通的团队成员可登录并查看全部商品；
- 已登录团队成员可编辑"内部备注"；
- v1 不提供商品删除、商品字段编辑和批次回滚；
- v1.1 增加管理员角色、成员管理、上传人删除和批次回滚。

## 4. 功能需求

### 4.1 用户认证（P0）

- 邮箱 + 密码登录；账号仅限已开通的团队成员使用；
- 登录状态保持（刷新不掉线）；
- 页面右上角展示当前登录用户邮箱；
- 未登录访问任何数据页时跳转到登录页。

### 4.2 员工每日工作导入（P0）

- 老板统一上传客服/员工提交的 `.xlsx` / `.xls` 文件；
- 上传时填写实际工作员工和工作日期，员工暂时不需要登录；
- Excel 固定字段为：`序号、货号、采集平台、采集商品名称、采集商品链接、采集规格、采集价格(CNY)`；
- 系统自动记录上传账号、上传时间、文件名和批次信息，Excel 不负责提供员工和工作日期；
- 导入过程显示进度（已写入 x / 共 y 行）；
- 单批建议 ≤ 5 万行，支持同一员工不同日期重复导入；
- 导入失败时提示失败范围，支持重试。

### 4.3 员工工作记录查看与筛选（P0）

- 工作明细分页展示（每页 100 条）；
- 按员工和工作日期筛选；
- 可按采集平台、货号和商品名称筛选（后续扩展）；
- 列表字段：员工、工作日期、货号、采集平台、采集商品名称、采集商品链接、采集规格、采集价格。

### 4.4 数据编辑（P0 / P1）

- 在线编辑"内部备注"并保存（P0，核心需求）；
- 编辑商品字段（货号、价格等）（v1.1）；
- 删除单条数据（仅上传人本人，v1.1）；
- 按导入批次批量删除 / 回滚（v1.1）。

### 4.5 导入追溯（P0）

- 每个员工工作批次必须包含员工姓名、工作日期、上传账号、文件名、行数和上传时间；
- 工作明细必须关联批次，不允许脱离批次写入；
- 上传账号从已验证登录令牌确定，不接受客户端伪造；
- 员工账号关联字段保留为空的能力，未来开通员工登录后再绑定 `employee_id`。

## 5. 非功能需求

| 维度 | 要求 |
|---|---|
| 数据规模 | 最多几十万行（按 50 万行设计），单条约 500 字节 |
| 并发 | 3~5 人同时在线操作 |
| 性能 | 列表翻页/筛选 < 1s；导入 5 万行 ≤ 2 分钟 |
| 可用性 | 国内访问稳定，工作日随时可用 |
| 成本 | 腾讯云轻量应用服务器约 20~50 元/月，整体月均 ≤ 50 元 |
| 安全 | 数据仅团队成员可见；上传人不可伪造 |
| 部署与资源 | 前端、API 和 PostgreSQL 共用一台腾讯云轻量应用服务器；单批导入不超过 5 万行，并监控 CPU、内存和磁盘空间 |
| 备份与恢复 | 先部署 Docker Compose 并确认 PostgreSQL 容器健康、数据库可连接，再接入每日 `pg_dump` → 腾讯云 COS 自动备份；至少保留 7~14 天，目标 RPO 不超过 24 小时；服务器故障时可在新服务器恢复业务 |
| 可维护性 | Docker Compose、自动备份和 AI 辅助维护，控制人工运维负担 |

## 6. 数据字典（v1）

### 6.1 员工工作批次表 `employee_work_batches`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | uuid | 系统 | 批次主键 |
| `employee_name` | text | 是 | 实际工作的员工姓名 |
| `employee_id` | uuid | 否 | 未来关联 `app_users.id`，当前员工不登录 |
| `work_date` | date | 是 | 员工实际工作日期 |
| `file_name` | text | 是 | 客服提交的文件名 |
| `uploaded_by` | uuid | 系统 | 老板上传账号 ID |
| `total_rows` | integer | 是 | 明细行数 |
| `created_at` | timestamptz | 系统 | 上传时间 |

### 6.2 员工工作明细表 `employee_work_items`

| Excel 列名 | 数据库字段 | 类型 | 说明 |
|---|---|---|---|
| 序号 | `seq` | text | 原始序号 |
| 货号 | `sku` | text | 商品货号 |
| 采集平台 | `platform` | text | 例如 1688 |
| 采集商品名称 | `name` | text | 商品名称 |
| 采集商品链接 | `url` | text | 商品链接 |
| 采集规格 | `spec` | text | 商品规格 |
| 采集价格(CNY) | `price` | numeric(14,2) | 人民币价格 |
| 系统字段 | `batch_id` | uuid | 关联员工工作批次 |

### 6.3 OZON 统计批次表 `ozon_statistics_batches`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | uuid | 系统 | 统计批次主键 |
| `file_name` | text | 是 | 统计文件名 |
| `uploaded_by` | uuid | 系统 | 上传账号 ID |
| `total_rows` | integer | 是 | 统计明细行数 |
| `created_at` | timestamptz | 系统 | 导入时间 |

### 6.4 OZON 统计明细表 `ozon_product_pricing`

OZON 统计表对应 `OZON-选品、定价表.xlsx` 模板。价格字段使用金额类型；重量单位为 kg；利润率、佣金比例和退货率按小数保存，例如 `10%` 保存为 `0.10`；价格检测和重量检测保存为布尔值；`price_1` 暂时只保存原始数值，不参与系统计算。

| Excel 列名 | 数据库字段 | 类型 | 说明 |
|---|---|---|---|
| 店铺 | `store` | text | 店铺名称 |
| 产品名称 | `product_name` | text | 商品名称 |
| 档口SKU | `supplier_sku` | text | 供应商 / 档口 SKU |
| 进价 | `purchase_price` | numeric(14,2) | 采购价格 |
| 重量kg | `weight_kg` | numeric(10,3) | 商品重量，单位 kg |
| [本店] SKU | `local_sku` | text | 本店 SKU |
| 姓名缩写 | `name_abbreviation` | text | 选品人或负责人缩写 |
| SKU前缀 | `sku_prefix` | text | SKU 前缀 |
| [本店]卖价 | `selling_price` | numeric(14,2) | 本店售价 |
| 实际利润率 | `actual_margin_rate` | numeric(7,4) | 按小数保存 |
| 保本卖价 | `breakeven_selling_price` | numeric(14,2) | 保本售价 |
| 价格检测 | `price_check` | boolean | Excel 的 1/0 转为 true/false |
| 重量检测 | `weight_check` | boolean | Excel 的 1/0 转为 true/false |
| 保本利润 | `breakeven_profit` | numeric(14,2) | 保本利润 |
| 保本利润率 | `breakeven_margin_rate` | numeric(7,4) | 按小数保存 |
| 价格1 | `price_1` | numeric(14,2) | 备用价格 |
| 运费 | `shipping_fee` | numeric(14,2) | 运费 |
| 佣金比例 | `commission_rate` | numeric(7,4) | 按小数保存 |
| 退货率 | `return_rate` | numeric(7,4) | 按小数保存 |
| 货源地址 | `source_url` | text | 货源链接 |
| 系统字段 | `created_by` / `created_at` / `updated_at` | 系统 | 服务端自动记录 |
| 统计批次 | `batch_id` | uuid | 关联 OZON 统计批次，可保留每次导入历史 |

## 7. 验收标准

1. 已开通负责人可以登录，未登录无法访问数据页面；
2. 导入员工工作 Excel 后，批次包含员工、工作日期、上传人和上传时间，每行明细关联批次；
3. 员工工作记录可以按员工和工作日期筛选，翻页正常；
4. OZON 统计数据每次导入都保留独立批次和历史明细；
5. 3 人同时使用无明显卡顿；
6. 5 万行导入可在 2 分钟内完成。
7. 生产环境先通过 Docker Compose 和 PostgreSQL 健康验收，再启用每日 `pg_dump` → COS 自动备份，并验证备份对象可下载和恢复。

## 8. 非目标（v1 不做）

- 复杂的角色权限系统（v1.1 再做管理员角色）；
- 多店铺 / 多部门数据隔离；
- 数据看板、统计图表；
- 移动端 App；
- 微信登录 / 消息通知。

## 9. 架构约束

- v1 使用腾讯云轻量应用服务器，React/Vite 构建产物、Hono.js/Node.js API 和 PostgreSQL 通过 Docker Compose 部署；
- 前端通过 HTTPS 调用 Hono.js/Node.js API，浏览器不得直接连接 PostgreSQL；
- 所有数据库访问必须经过后端服务层封装，页面组件不得直接依赖数据库驱动；
- API 必须从已验证的登录令牌确定当前用户，`created_by` 不接受客户端传入；
- 业务数据关联自有 `app_users` 表，使用标准 PostgreSQL 类型、外键、索引和事务；
- PostgreSQL 不开放公网端口，数据库密码、JWT 密钥和备份凭据不得进入前端或代码仓库；
- React/Vite 构建产物、Hono.js API 和 PostgreSQL 均部署在同一台腾讯云轻量应用服务器；
- Nginx 提供前端静态文件、HTTPS 和 `/api` 反向代理，Hono.js API 与 PostgreSQL 只通过 Docker Compose 内部网络通信；
- Docker Compose 配置服务开机启动和异常重启；服务器防火墙只开放 80、443 及受限 SSH，PostgreSQL 端口不对公网开放；
- 服务器已完成 COS 基础配置；后续必须先部署 Docker Compose，确认 PostgreSQL 容器状态健康且数据库可连接，再启用每日 `pg_dump` → COS 定时备份；
- COS 备份至少保留 7~14 天，并定期执行恢复演练；v1 不承诺单机高可用；
- 后续如需迁移到云数据库或 BaaS，应保留现有业务表和 API 服务接口；
- v1 不引入 Kubernetes、消息队列、操作审计、修改历史和删除日志。
