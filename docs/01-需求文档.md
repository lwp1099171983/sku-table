# 选品工作台需求文档（v2.1）

## 1. 项目概述

| 项目 | 内容 |
|---|---|
| 项目名称 | 选品工作台（sku-table） |
| 目标用户 | 电商小团队 3~5 人（管理员、组长、客服） |
| 核心价值 | 按店铺集中管理员工工作记录与订单台账，Excel 导入后统一筛选、统计与删除 |
| 形态 | Web 应用（PC 浏览器为主），内部使用，非商业产品 |

## 2. 背景与问题

- 现状：员工采集数据与订单统计表散落在各人 Excel 里，通过微信/网盘传来传去，版本混乱，无法按店铺汇总。
- 痛点：
  1. 员工每天采集了什么商品、哪个店铺的数据，没有统一入口追溯；
  2. 订单台账（售价、采购、运费、广告等）统计靠手工在 Excel 里维护，容易出错；
  3. 组长、客服需要按店铺隔离权限，管理员需要看全部店铺汇总。
- 目标：一个"登录即可用"的网页工具：员工工作 Excel 导入 → 筛选/追溯/删除；台账 Excel 导入 → 顶部统计自动汇总（随筛选变化）；按店铺分配角色与删除权限。

## 3. 用户角色与权限

采用**按店铺隔离的 RBAC 权限模型**：管理员为全局账号（看全部店铺、拥有全部权限）；组长/客服由管理员创建账号并分配到具体店铺。权限默认拒绝，账号通过"店铺成员 + 角色 + 用户级 allow/deny"获得权限；用户级 deny 优先于角色 allow；JWT 只存用户 ID，权限由服务端按当前店铺实时计算。

### 3.1 角色

| 角色 | 说明 | 预置权限 |
|---|---|---|
| admin（管理员） | 全局账号，创建店铺/成员，看全部店铺 | 全部 13 个权限码 |
| leader（组长） | 相当于店长，看被分配店铺的两个表，但不可看台账统计 | `employee_work.read/import`、`ledger.read/import` |
| customer（客服） | 查看和导入被分配店铺的员工工作记录 | `employee_work.read/import` |

- `ledger.edit`、`employee_work.delete`、`ledger.delete` **不预置给普通角色**，由管理员在成员管理中按用户、按店铺单独开通 allow/deny；管理员默认拥有全部权限。
- 管理员账号通过注册管理员页创建（全局）；组长/客服账号由管理员在"店铺与成员"页创建并分配店铺。

### 3.2 权限矩阵（13 个权限码）

| 权限码 | admin | leader | customer |
|---|---:|---:|---:|
| `shop.manage` | ✓ | — | — |
| `member.read` | ✓ | — | — |
| `member.manage` | ✓ | — | — |
| `user.manage` | ✓ | — | — |
| `employee_work.read` | ✓ | ✓ | ✓ |
| `employee_work.import` | ✓ | ✓ | ✓ |
| `employee_work.delete` | 用户级开通 | 用户级开通 | 用户级开通 |
| `employee_work.rollback` | ✓ | — | — |
| `ledger.read` | ✓ | ✓ | — |
| `ledger.stats.read` | ✓ | — | — |
| `ledger.import` | ✓ | ✓ | — |
| `ledger.edit` | ✓ | 用户级开通 | 用户级开通 |
| `ledger.delete` | 用户级开通 | 用户级开通 | 用户级开通 |

### 3.3 权限规则

- 仅启用状态（`is_active = true`）的账号可登录；管理员账号为全局，组长/客服必须属于至少一个店铺才能登录；
- 店铺切换：组长/客服被分配多个店铺时默认进入"全部店铺"，并可在顶部切换具体店铺；只有一个店铺时普通成员直接进入该店铺且不显示切换器，管理员始终显示；全部视图在两个业务页面显示店铺列；
- 组长/客服的"全部店铺"仅汇总本人被分配且启用、并具备对应查看权限的店铺；请求其他店铺数据返回 403；
- 组长/客服只要是店铺的启用成员即可向该店铺导入员工工作；台账编辑权限（`ledger.edit`）和删除类权限（`employee_work.delete` / `ledger.delete`）默认不授予，管理员在成员管理中按店铺、按用户开通 allow / deny；
- 删除语义：员工工作明细硬删除且不可恢复；台账明细软删除，记录删除时间和操作者。两类删除均同步扣减所属导入批次的有效 `total_rows`（不低于 0）。

## 4. 功能需求

### 4.1 员工工作记录

- 数据来源：Excel 导入（模板 7 字段：序号、货号、采集平台、采集商品名称、采集商品链接、采集规格、采集价格(CNY)）；必须先切换到具体店铺，处于"全部店铺"时点击导入需提示先选择店铺；支持一次选择最多 20 个 Excel，各文件单独生成批次并逐个导入，单文件失败不阻断后续文件；纯客服角色导入时员工姓名由服务端强制使用当前账号姓名（未设置姓名时使用邮箱），无需填写，组长/管理员仍可选择或输入员工姓名；货号必填，同一店铺内忽略大小写唯一，文件内重复货号保留第一条，已存在于该店铺的货号不重复导入；
- 列表：按 员工 / 日期 / 货号 筛选，分页展示；
- 删除：行首勾选框，支持单行删除与勾选多行批量删除，二次确认后硬删除；删除权限按店铺由管理员配置；
- 模板文件当前不在页面提供下载入口；导入批次记录导入来源（文件名、员工、日期、行数），列表页提供「导入记录」入口，按批次查看导入来源与状态；
- 按批次回滚（`employee_work.rollback`，仅管理员）：回滚后该批次明细从默认列表与统计中隐藏，批次记录保留可追溯。

### 4.2 台账（订单统计表）

- 数据来源：纯 Excel 导入，不做手工录入；导入按 Excel"店铺"列文本归类到对应店铺，店铺不存在时自动创建，并把导入者自动加入新店铺以保证可见；已存在的店铺必须是导入者被分配的店铺（管理员除外），否则拒绝写入（403）；
- 字段字典（25 个，使用 SKU；尾程、毛利、净利和广告净利按系统公式计算）：

  `序号、月份、订单日期、店铺、订单号、SKU、售价、数量、单价、采购金额、采购日期、采购平台、采购订单号、毛利、渠道名称、包裹重量、运费、抽点、净利、广告22%、22%净利、广告30%、30%净利、尾程、备注`

- 说明：用户 Excel"订单统计表"实际有 29 列（多出品名、产品图、规格型号、单位、产品ID、SKU）；解析时只映射上述字段，同时兼容旧表头"跟踪号"和"赔偿"（映射为尾程）；"数量"对应 Excel"产品ID"列；"月份"为空时按订单日期自动填充；"序号"为空时按导入顺序自动生成；尾程为比例，缺失时默认 `2%`；表头可能带有"超重""渠道不存在或公式错误"等文本，按原始值保存；
- 订单号：去除首尾空格后在当前台账中全系统唯一，文件内、历史数据和并发冲突的重复行跳过；已软删除订单可重新导入；空订单号允许导入；SKU 可以重复。
- 列表：默认仅显示当前台账，按订单月份区间 / 店铺 / 订单号或采购订单号关键字 / SKU / 净利、22%净利、30%净利是否亏损筛选，分页展示；三个亏损筛选可组合使用，仅匹配有效负数；订单号、采购订单号和 SKU 输入框采用防抖查询；月份使用月度区间控件，首次进入及点击清除筛选后均为当前年份 1 月至当前月；明细不展示数量和单价，包裹重量紧随采购金额；店铺、SKU、渠道名称使用紧凑列宽，明细文本溢出时显示省略号，悬停展示完整值。
- **顶部统计（8 项，随筛选结果变化；仅拥有 `ledger.stats.read` 权限的账号可见）**：

| 统计项 | 口径 |
|---|---|
| 采购金额 | SUM(采购金额) |
| 营业额 | SUM(售价) |
| 毛利润 | 营业额 − 采购金额 − 尾程金额 |
| 运费 | SUM(运费) |
| 抽点 | SUM(抽点) |
| 净利润 | 毛利润 − 运费 − 抽点 |
| 提现费用 | (营业额 − 运费 − 抽点) × 1% |
| 纯利润 | 净利润 − 提现费用 |

- 删除：行首勾选框，支持单行删除与勾选多行批量删除；删除后默认列表、顶部统计和所属导入批次有效行数同步变化，保留删除时间和操作者。删除权限按店铺由管理员配置；页面暂不提供回收站和恢复操作。
- 尾程：先把人民币售价按固定汇率换算为卢布，按尾程比例计算并限制在 `15~200 RUB`，再换回人民币；当前固定汇率为 `1 RUB = 0.0822 CNY`，配置在 `apps/api/src/config/exchangeRate.ts`。
- 物流资费：资费表按“版本 + 规则”保存到数据库，初始版本包含源 Excel 的 89 条渠道规则；仅管理员可在“物流资费”页导入新版 Excel、查看规则并显式启用，同一时刻只能启用一个版本。导入文件须含“渠道名称、价格公式（自提点）、重量限制”列，价格公式和重量范围解析失败、渠道重名时拒绝导入。
- 重量编辑：拥有 `ledger.edit` 的账号可在线编辑包裹重量；重量必须为大于等于 0 的数字，保存时按当前启用的物流资费版本重算尾程、毛利、运费、抽点、净利、广告22%、22%净利、广告30%、30%净利，并保存实际使用的资费版本。新版本只影响之后保存的重量重算，已重算台账保留原版本和结果；超重、未知渠道或金额非法时拒绝保存。
- 金额精度：重量重算使用十进制计算，尾程、毛利、运费、抽点、净利及广告相关金额均按 `ROUND_HALF_UP` 四舍五入为两位小数；净利基于已舍入的毛利、运费和抽点计算，广告净利基于已舍入的净利和广告费用计算。顶部统计汇总已保存金额，并将各统计项四舍五入为两位小数；重量不按金额规则补零。

### 4.3 店铺与成员管理（管理员）

- 创建店铺（名称唯一）；删除店铺（二次确认后级联删除该店铺的成员关系、员工、工作记录与台账，且不可恢复）；
- 查看/添加/修改/移除店铺成员：添加成员时可按邮箱搜索已有账号直接加入（无需重复设置密码），新邮箱则创建账号（邮箱+密码）并分配角色（组长/客服，可多角色）；已是该店铺成员的账号添加时提示冲突；
- 按店铺、按用户开通或关闭台账编辑和删除权限（`ledger.edit` / `employee_work.delete` / `ledger.delete` 的 allow/deny/未开通）；
- 账号管理（管理员）：跨店铺查看全部组长/客服账号及所属店铺与角色；重置成员密码；停用/启用账号（停用后登录被拒、所有店铺访问立即失效，成员关系保留，重新启用即恢复）；
- 用户自助修改密码（登录后顶部用户菜单进入，需验证旧密码；改密后旧登录态不强制下线）；
- 注册管理员：创建全局管理员账号。

说明：账号级操作仅针对非管理员成员（组长/客服），管理员账号之间不可互操作，管理员也不能停用/重置自己的账号；自己改密通过"修改密码"入口完成。

### 4.4 登录与基础能力

- 邮箱 + 密码登录，账号由管理员预先创建或 seed 初始化，不开放公开注册；
- 登录后自动加载"可访问店铺 + 当前店铺 + 角色 + 权限"，多店铺组长/客服默认选择"全部店铺"；
- "全部店铺"视图下，员工工作与台账列表显示店铺列；管理员统计为全店汇总，组长仅可查看本人有权限店铺的台账明细，不返回统计数据；
- 登录页支持"记住账号"（仅记住邮箱，不保存密码）；顶部支持浅色/深色主题切换。

## 5. 非功能需求

- 单文件 ≤ 20MB，单批最多 5 万行；服务端解析 Excel，分块写入；
- 权限默认拒绝，越权请求返回 403；API 不接受客户端传入的身份、角色、权限、店铺归属；
- 金额/比例由应用计算规则保护（员工工作价格非负；台账导入保留 Excel 原值，重量在线编辑严格校验）；
- API 记录请求路径、状态码和耗时；台账导入额外记录用户 ID、文件名/大小、解析行数、店铺数、导入/跳过数量、批次 ID 和失败原因，不记录订单内容、JWT 或密码；
- 迁移：基线 + 增量 SQL 迁移，advisory lock 防并发，执行前 `pg_dump` 备份。

## 6. 验收标准

- `pnpm typecheck` 与 `pnpm build` 全部通过；
- 员工工作：多文件导入前必须选择具体店铺，组长/客服只要是该店铺启用成员即可导入；纯客服导入自动归属当前账号姓名，客户端传入其他员工姓名也会被服务端覆盖；每个文件单独生成批次并汇总成功/失败/新增/跳过数量；同一店铺内货号忽略大小写去重，文件内重复和历史已存在货号均不重复入库；导入 → 筛选 → 单行删除 → 批量删除后，批次 `total_rows` 正确递减；无 `employee_work.delete` 权限时 403；「导入记录」可查看批次来源，管理员回滚后批次数据从列表隐藏、批次记录保留；
- 台账：多店铺 Excel 导入自动归类/创建店铺；当前台账订单号全系统不重复且返回跳过数量，SKU 可重复；已删除订单可重新导入；尾程空值默认 `2%`，按卢布限额换算为人民币并参与毛利、净利和广告净利计算；净利、22%净利、30%净利可分别筛选有效负数，组合筛选后的列表与统计一致；管理员可导入并启用物流资费新版本，重量编辑按启用版本重算且保存资费版本；顶部统计同步变化；有统计权限时筛选后统计区数值与 4.2 公式一致；删除后统计与批次有效行数同步变化，页面不提供回收站和恢复操作；
- 日志：可从 API 日志判断台账导入请求是否到达、文件是否解析成功、事务是否成功写入，以及实际导入/跳过行数；
- 权限：管理员看全部店铺汇总；组长只看被分配店铺、可看可导入但不可看台账统计；客服可查看和导入被分配店铺的员工工作；管理员可单独给成员开通台账编辑或删除；台账导入遇到非本人店铺名返回 403；
- 账号：管理员账号页可查看账号店铺归属、重置密码、停用/启用；停用账号登录返回 401、旧 token 立即失效；重置/改密后可用新密码登录；
- 店铺切换：多店铺组长/客服默认进入"全部店铺"并可在顶部切换，单店铺普通成员不显示切换器，管理员始终可选"全部店铺"；
- 迁移：空库执行新基线成功；旧库执行增量迁移成功（表名/字段改名正确，商品表已删）。
