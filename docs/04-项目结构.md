# 项目结构约定

## 目标

项目采用 pnpm workspaces 管理前端、后端和共享代码。目录边界对应部署边界，避免页面、API、数据库配置和运维脚本混在同一个 `src` 目录。

## 目录职责

| 目录 | 职责 | 依赖方向 |
|---|---|---|
| `apps/web` | React/Vite 页面、布局、前端 services | 依赖 `packages/shared`，通过 HTTP 调用 API |
| `apps/api` | Hono 路由、中间件、认证、业务服务和数据库访问 | 可依赖 `packages/shared`，不被页面代码反向依赖 |
| `packages/shared` | DTO、领域类型和跨端常量 | 不依赖前端、Node 或数据库驱动 |
| `infra/docker` | Docker Compose、服务编排和生产环境变量约定 | 只负责部署，不放业务代码 |
| `infra/nginx` | 静态文件和 `/api` 反向代理配置 | 只负责入口和网络转发 |
| `infra/scripts` | 备份、恢复、健康检查等运维脚本 | 调用部署工具，不被业务代码导入 |
| `infra/legacy/supabase` | 历史兼容迁移材料 | 不参与 v1 主流程 |
| `docs` | 需求、技术选型、任务拆分和结构约定 | 不被运行时代码依赖 |

## 新功能放置规则

- 新页面放在 `apps/web/src/pages`，页面通过 `apps/web/src/services` 访问 API。
- 新 API 路由放在 `apps/api/src/routes`，认证和通用错误处理放在 `middleware`。
- 数据库 schema、迁移和 repository 只放在 `apps/api`，禁止从前端导入。
- 前后端都需要的请求/响应类型放在 `packages/shared/src`。
- Docker、Nginx、备份和恢复脚本放在 `infra`，不要放进应用源码目录。

## 本地启动

在仓库根目录执行 `pnpm install` 后，分别运行 `pnpm dev:web` 和 `pnpm dev:api`。前端默认请求 `http://localhost:3000/api`，可在 `apps/web/.env` 覆盖。
